## Mux 开启 2160p（4K）转码的完整方案

### 一、核心机制

Mux 默认 **不会自动** 将视频转码为 4K。要开启 2160p，必须在创建资产（Asset）时显式指定两个字段：

| 字段 | 值 | 说明 |
|------|-----|------|
| `max_resolution_tier` | `"2160p"` | 控制最大转码、存储、分发分辨率（可选：`1080p` / `1440p` / `2160p`，默认 `1080p`） |
| `video_quality` | `"basic"` 或 `"plus"` 或 `"premium"` | 编码质量层级。Basic 套餐现在也免费支持 4K（2026 更新） |

---

### 二、API 调用示例

#### 1. Pull 模式（Mux 从 R2 拉取，推荐）
```json
POST /video/v1/assets
{
  "input": [{ "url": "https://pub-xxx.r2.dev/test.mp4" }],
  "playback_policy": ["public"],
  "passthrough": "test.mp4",
  "video_quality": "basic",
  "max_resolution_tier": "2160p"
}
```

#### 2. Direct Upload 模式（本地上传）
```json
POST /video/v1/uploads
{
  "new_asset_settings": {
    "playback_policy": ["public"],
    "video_quality": "basic",
    "max_resolution_tier": "2160p"
  },
  "cors_origin": "*"
}
```

### 四、4K 输入文件规范（避免非标准化处理）

为了让 Mux 以 **最快速度** 完成 4K 转码（无需二次标准化），源文件建议满足：

| 限制项 | 要求 |
|--------|------|
| 最大尺寸 | ≤ 4096×4096 像素（宽或高任一维度） |
| 关键帧间隔 | ≤ 10 秒（HEVC 亦然） |
| 平均码率 | ≤ 20 Mbps（GOP 峰值 ≤ 40 Mbps） |
| 帧率 | 5 ~ 60 fps（>60fps 视为非标） |
| 编码 | H.264 或 HEVC（H.265），Closed GOP |
| 色彩 | 8-bit 4:2:0 或 HEVC 下 10-bit 4:2:0 |
| 音频 | AAC（单声道/立体声/5.1） |

> 不符合以上规范的输入仍能处理，但 Mux 会先做一次「标准化转码」再做阶梯转码，整体耗时显著增加。

### 五、分级播放控制（会员等级常用）

4K 资产生成后，Mux 会在 HLS Master Playlist 中自动包含 1080p / 1440p / 2160p 等多层 rendition。如果只想给部分用户（如高级会员）开放 4K，可在播放 URL 上 Query：

```
# 限制最高 1080p（普通会员）
https://stream.mux.com/{PLAYBACK_ID}.m3u8?max_resolution=1080p

# 限制最高 1440p（黄金会员）
https://stream.mux.com/{PLAYBACK_ID}.m3u8?max_resolution=1440p

# 不限制，最高 2160p（白金会员，默认）
https://stream.mux.com/{PLAYBACK_ID}.m3u8
```

这个机制正好可以与 iSEE 项目后续的会员体系（Stripe/PayPal/USDT）打通。

## 四、Delivery（分发/播放流量）费用详解

这是实际花费中**最容易爆发**的一块，也是 Mux 区别于按 GB 计费平台的核心。

### 常规分发价（Basic/Plus 通用，超 10 万分钟后）
| 播放最高分辨率 | 单价 | 相对于 720p 倍数 |
|---------------|------|----------------|
| ≤720p | **$0.0008 / min** | 1x |
| 1080p | **$0.0010 / min** | 1.25x |
| 1440p (2K) | **$0.0016 / min** | 2x |
| **2160p (4K)** | **$0.0032 / min** | **4x** |

### 计费关键规则（容易踩坑）
1. **按「实际播放器选择的最高层级」计费**，而不是按资产生成的最高层级
   - 例：资产是 4K 的，但观众播放时播放器因网速只拉到 1080p → 按 $0.0010/min 收，不是 $0.0032
2. **缓冲也算**：播放器预加载的 10~30 秒分片，无论观众有没有真正看到，都算 delivery
3. **分钟不四舍五入**：看了 37 秒就按 37 秒算，不按 1 分钟
4. **ABR 多码率只按最终播放层级算一次**（不是把所有 rendition 的字节加起来）

### 用「?max_resolution=」控制 Delivery 成本（强烈推荐）
在播放 URL 后加参数强制封顶，直接省钱：

```
普通会员（最多 1080p）：
https://stream.mux.com/{PID}.m3u8?max_resolution=1080p  →  $0.0010/min

白金会员（4K 全开）：
https://stream.mux.com/{PID}.m3u8                          →  $0.0032/min（最高）
```

这正好可以和 iSEE 后续的订阅等级打通。

## 七、成本优化的 5 条具体建议（直接改项目）

1. **保留 `video_quality = "basic"`** — 目前 iSEE 片库 4K 转码完全免费，别切 Plus/Premium。
2. **在会员鉴权层给播放 URL 拼 `?max_resolution=`** — 普通用户最多给 1080p，直接把 Delivery 成本砍 60%+。
3. **播放器设置合理的 buffer（比如 10s）**，别默认预缓冲 60s，Delivery 是算分片字节数对应的分钟数的。
4. **长尾冷门内容自动删 playback_id** — 没观众时把 playback_id 清掉（资产保留），避免被盗链消耗 Delivery 额度（要用时再 `POST /playback-ids` 重建，免费）。
5. **Delivery 10 万分钟免费额度先吃满再评估成本** — MVP 阶段大概率在免费额度内，不用急着换 Cloudflare Stream。
